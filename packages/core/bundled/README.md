- `ponytail/skills/`: the `ponytail`, `ponytail-review`, `ponytail-audit` and `ponytail-debt` skills (the help / scoreboard cards and the Claude Code hooks are left out).
- `agent-skills/`: `skills/` and `references/` as published, plus `agents/accessibility-auditor.md` (the persona `accessibility-engineering` links to). Updated from `aeac41d` (2026-10-13) to `222bf92` (2026-11-18, the merge of #261): new skill `accessibility-engineering` (WCAG 2.2 AA audits; its automated step runs `npx --yes @axe-core/cli@4.13.0` and `npx --yes pa11y@9.1.1`, and `scripts/audit-a11y.sh` runs both, so those tools are downloaded from npm when an agent uses them; Aivenue installs nothing and the agent runs them like any other command, under the run's permission); revised wording in most other skills and in the accessibility, performance, security and testing references; a `quality-gate.mjs` script added to `constraint-driven-development` (off by default). No skill was removed or renamed.
- `security-audit/skills/security-audit/`: `SKILL.md` and its 14 companion files, unchanged. Left out: `report-schema.json`, `validate-findings.cjs`, `validate-coverage-ledger.cjs` and their tests, used only by the full audit mode, which Aivenue does not run yet. Aivenue offers this skill only as a per-workflow "security check" for the code reviewer, in guidance mode and static only (`docs/next-task-security-audit-skill.md`).
- `gh-fix-ci/skills/gh-fix-ci/SKILL.md`: unchanged. Left out: `scripts/inspect_pr_checks.py`, `agents/openai.yaml` and `assets/`. Aivenue runs the same steps itself in Node (`packages/core/src/ciDiagnose.ts`, written after that script, read only, no Python needed) when a request asks about failing GitHub PR checks, and gives the result and this skill to the agent doing the work.
- `gh-address-comments/skills/gh-address-comments/SKILL.md`: unchanged. Left out: `scripts/fetch_comments.py` (it reads the PR in its head repository, which is wrong for a PR from a fork, and needs Python), `agents/openai.yaml` and `assets/`. Aivenue reads the unresolved review threads itself in Node (`packages/core/src/prReviews.ts`, read only) when a request asks to address a PR's review comments.
- `architecture-review/skills/`: `improve-codebase-architecture/` (`SKILL.md`, `HTML-REPORT.md`) and `codebase-design/` (`SKILL.md`, `DEEPENING.md`, `DESIGN-IT-TWICE.md`), unchanged; `agents/openai.yaml` left out. One switch for both. Aivenue tells the planner to report in Markdown in its reply (no HTML file, browser or CDN), list the candidates and stop, since the `grilling` and `domain-modeling` skills it hands off to are not shipped (`PACK_SKILLS` in `packages/core/src/extensions.ts`).
- `diagnosing-bugs/skills/diagnosing-bugs/`: `SKILL.md` and `scripts/hitl-loop.template.sh`, unchanged; `agents/openai.yaml` left out. Aivenue tells agents to ask with `ask_user` instead of running the terminal script.
- `gha-security-review/skills/gha-security-review/`: `SKILL.md` and its 9 `references/`, unchanged. The references quote real attack payloads; Aivenue tells the code reviewer to review statically and never run them.
- `web-design-guidelines/skills/web-design-guidelines/`: `command.md` is the upstream rules file, unchanged. `SKILL.md` is Aivenue's own: the upstream `SKILL.md` (in a repository without a LICENSE file) fetches `command.md` from `main` at every run; Aivenue's reads the pinned copy and never fetches.
- `obsidian-skills/skills/`: `obsidian-markdown/` (`SKILL.md`, `references/CALLOUTS.md`, `EMBEDS.md`, `PROPERTIES.md`), `json-canvas/` (`SKILL.md`, `references/EXAMPLES.md`) and `obsidian-bases/` (`SKILL.md`, `references/FUNCTIONS_REFERENCE.md`), unchanged, from 2026-11-06 (the repository was `kepano/obsidian-skills`, now `obsidianmd/obsidian-skills`). One switch for the three, offered to the implementer, sub-agents and the code reviewer. Left out: `obsidian-cli` (drives a running Obsidian desktop app through its CLI and local socket, and can run JavaScript in it: nobody can open the app or answer for it during a run), `defuddle` and `knap` (npm tools the skills offer to install globally; defuddle fetches web pages), the plugin manifests and `scripts/bump.sh`. No file in the three skills starts with `#!`. Aivenue's rule tells agents to write the files directly and not to install or run the obsidian command, Defuddle or Knap.
- `egm/`: from `v0.1.1` (2026-11-06), unchanged: `skills/egm-draft/` (`SKILL.md`, `references/design_doc.md`), `skills/egm-review/SKILL.md`, `skills/egm-resolve/SKILL.md`, nine personas in `agents/` (`zoom_out`, `comprehension`, `design_critic`, `implementation_readiness`, `inventive_catalyst`, `structural`, `style`, `codebase_details`, `synthesizer`) and `resources/` (`execution_instructions.md`, `document_standards/`), at the same relative paths as upstream so the skills' links resolve. `AIVENUE.md` is Aivenue's own: it maps EGM onto a workflow and wins over the upstream text where they disagree. The adaptations: (1) the Elephant is the plan author and the design document is the plan it submits (plan authors write no files in Aivenue; upstream writes `design_draft.md` / `docs/designs/`); (2) no brainstorm, no one-question-per-turn or go-ahead gates, no preset menu: open questions go into the document, the reviewer runs the "consolidated" preset (stages 5–9) straight through; (3) the Goldfish is Aivenue's plan reviewer, a fresh session (usually another provider) that never saw the author's conversation, and, when the workflow allows sub-agents, one read-only sub-agent per persona spawned with Aivenue's `spawn_subagent` and given only the document and its persona file, so EGM never stops for lack of a CLI-specific subagent tool (upstream: Claude Code `Agent`, Codex `spawn_agent`, Antigravity `invoke_subagent`); (4) the review is the reviewer's report (reviewers write no files; upstream writes `consolidated_review_report.md`); (5) the loop is Aivenue's plan review loop, and the author answers findings with `egm-resolve`'s categories without its interactive gates. One switch, off by default: `egm-draft` and `egm-resolve` for the plan author, `egm-review` for the plan reviewer, each with a rule pointing to `AIVENUE.md` (`PACK_SKILLS.egm` in `packages/core/src/extensions.ts`). Left out: `egm-bootstrap` (writes README.md files across a repository subtree), `egm-brainstorm` (an interview), `egm-drift-report` (a whole-repository report outside a workflow), `egm-review-loop` (its own multi-agent loop, replaced by Aivenue's), the `bootstrap_orchestrator` persona, the per-CLI docs, plugin manifests, `openai.yaml` and icons, tests and the site. `egm-lite` came after the pinned tag. No file starts with `#!`.
- Turned on one by one under Capabilities → built-in skills you can turn on; off by default. A skill that is on is offered to its roles every time (in their skills index) and the agent decides from the task whether to read it; Aivenue does not check the changed files first.
- Evaluated and not bundled: `frontend-testing-debugging` (openai/plugins `d420d13`: relies on Codex's Browser plugin, and the repository has no LICENSE file), `accessibility-inspect` (AccessLint/skills `2e9d733`: needs files and an MCP server that are not part of it, tells the user to install tools, and the repository has no LICENSE file). They are design references only.
- `impeccable/skills/impeccable/`: the skill as its 4.8.0 release publishes it for agents (`SKILL.md`, `reference/`, `agents/`, `scripts/`: the `impeccable` / `impeccable.cmd` launchers, `VERSION` 0.1.18, `engine-checksums.txt`, the browser scripts of its live mode and `data/`), unchanged; the `.cmd` launcher keeps CRLF line endings (`.gitattributes`). The engine binary is not bundled: when the extension is turned on, Aivenue installs npm `impeccable@4.8.0` into `<data>/tools/impeccable` with `npm --prefix`, which brings `@impeccable/cli-<os>-<arch>@0.1.18` (the engine) as an optional dependency, checked against the registry's integrity hash. The agents' commands get `IMPECCABLE_BIN` pointing at it, telemetry and update checks off, and impeccable's own files redirected into that folder (`packages/core/src/impeccable.ts`). `impeccable install` (which copies the skill into a project's or the user's agent folders and can add hooks) is never run. Earlier this skill was evaluated at `687bc38` and left out because it needed its CLI, detector and browser; the npm engine and the launcher's `IMPECCABLE_BIN` now cover that.
- `graphify/skills/graphify/SKILL.md` is upstream `graphify/skill-agents.md`; `graphify/always-on.md` is upstream `graphify/always_on/agents-md.md`. The `graphify` command itself (PyPI `graphifyy`) is installed with uv when the extension is turned on.

OmniRoute (https://github.com/diegosouzapw/OmniRoute, MIT) is not bundled: it is installed from npm when turned on.
